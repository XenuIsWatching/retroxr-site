The PlayStation is the platform that best shows what RetroXR does with saves. Your save is
not a hidden file in a folder — it is on a **memory card**, and the card is an object you
hold, slot in, and can lose.

## Before anything: the BIOS

The PlayStation will not boot without its BIOS, and RetroXR cannot ship it. Open `CORES` →
**BIOS / Extras** and pick PlayStation to see exactly which files it wants.

<Image src={biosPsx} alt="The BIOS / Extras view for PlayStation, listing scph5500.bin, scph5501.bin, scph5502.bin and psxonpsp660.bin with their required or optional status and per-file download buttons." />

The filenames have to match exactly — `scph5500.bin`, `scph5501.bin`, `scph5502.bin` and
`psxonpsp660.bin`. A file that is right in every way except its name will not be found.

If you run a [RomM](https://romm.app) server holding your firmware, RetroXR can pull these
down directly. Otherwise copy them in the usual way — see
[adding your games](/guide/adding-games/) and [BIOS files](/guide/cores/bios/).

## Memory cards

	src="/video/ps1/memory_card.mp4"

	caption="A memory card. Slot it into the console's card port; your saves live on it, not in a folder."
/>

<Image src={cardAnnotated} alt="A PlayStation memory card with two parts circled: the connector edge marked 1, and the printed label reading MEMORY CARD 1 marked 2." />

**① The connector edge** goes into the console's card slot. **② The label** names the
card, which is how you tell two of them apart on a shelf.

### Using one

<Steps>

1. Spawn a **memory card** from `SPAWN` → **Objects**.

2. Push it into one of the console's two card slots.

3. Play. The game saves to that card, in that slot.

</Steps>

Because a card is a real object rather than a setting, the things you could do with a real
one work here:

- **Keep several saves on one card**, until it runs out of blocks.
- **Move a save from one card to another.**
- **Delete a save** to free blocks.
- **Back a card up** to your RomM server.

There is a manager for all of this, reachable from the card itself: point at it and press
the **menu button**.

As of v0.4.0 the running game notices when **card slot 1 is emptied**, the way the console
did — pull the card mid-game and the machine sees it go.

<Aside type="tip" title="If a game cannot find your save">
	Saves are per card, and per slot. The usual cause is a different card in the slot, or
	the right card in the wrong slot. Check the card before suspecting the emulator.
</Aside>

<Aside type="caution" title="You cannot delete a save while the console is on">
	Power the machine down first. It is the same rule cartridge saves follow — see
	[game saves and backups](/guide/connecting/saves/).
</Aside>

### Where a card lives on disk

Each card is one ordinary `.mcr` image — the same 128 KB format any PlayStation memory card
tool on your PC will open.

```
libretro/save/memcards/playstation/<card name>.mcr
```

| Platform | Full path |
| --- | --- |
| Windows | `%USERPROFILE%\retroxr\libretro\save\memcards\playstation\` |
| Linux / macOS | `~/retroxr/libretro/save/memcards/playstation/` |
| Quest | `libretro/save/memcards/playstation/` in the [web file manager](/guide/adding-games/) |

Two things about that path are deliberate and worth knowing.

**The card's name is its filename.** Renaming a card in the manager renames the file, so
the folder reads as a shelf of cards rather than a pile of hashes. Which also means the
name has to survive being a filename — the manager strips characters your operating system
would refuse.

**There is no core in the path.** Compare that with everything else under `libretro/`,
which is filed per core — BIOS, core assets, cartridge battery saves. A card is *hardware*,
and the raw image is identical for every PlayStation core, so a card follows you when you
switch cores exactly as a real one follows you when you switch consoles. Cartridge saves do
not; see [the libretro folder](/guide/cores/downloading/#where-all-of-this-actually-lives).

<Aside type="caution" title="On Quest, copy cards OUT but not back IN">
	Reading a card off the headset is fine. Copying one back is not — a file pushed from a
	PC lands owned by the shell rather than the app, and RetroXR can no longer write your
	saves into it. A card it cannot update looks exactly like a card that was wiped. Use
	RomM to restore, or let the app write a fresh card.
</Aside>

### <RommMark />Backing a card up to RomM

A card you can lose is a card worth backing up, and this is the reason to connect a
[RomM](https://romm.app) server even if you copy your games across by hand.

<Steps>

1. [Connect RomM](/guide/connecting/romm/).

2. Back the card up from its own manager.

3. The card's contents live on your server, not only on the headset.

</Steps>

That matters more here than for most saves: on a Quest you cannot safely copy save files
back **in** from a PC — files pushed from a computer land owned by the shell rather than
the app, and RetroXR can no longer write to them. RomM is the route that avoids the
problem entirely.

Full detail on [game saves and backups](/guide/connecting/saves/).

## Discs

Spawn a game from `SPAWN` → **Games** and it arrives as a disc rather than a
cartridge. Open the console's lid, set the disc in the tray, close it, and power on.

Multi-disc games work — RetroXR retrieves the right image for each disc rather than
handing every disc the first one, which was a real bug fixed in
[v0.3.0](/blog/).

Multi-disc games can also be **swapped mid-game** on cores that support disc control: take
disc 1 out and put disc 2 in, and the game carries on. Pulling a disc no longer switches
the machine off either — see [cartridges and discs](/guide/playing/cartridges-and-discs/).

## Controllers

Both PlayStation pads are modelled, and which one you plug in is what decides how the
console reads it — there is no controller-type setting to find.

	caption="The original digital pad. Plug it in and the core switches to the standard controller."
/>

<Turntable
	src="/video/ps1/dualshock.mp4"
	poster={dualshockPoster}
	alt="The DualShock controller rotating, showing its two analogue sticks, the ANALOG button between them, the D-pad and the four face buttons."
	caption="The DualShock. Plug it in and the core switches to the dual-shock controller — sticks and all."

Push either into one of the two controller ports on the front:

- **The original pad** selects the standard controller.
- **The DualShock** selects the dual-shock controller.

**The ANALOG button works.** Put a fingertip on it and press, and the DualShock drops back
to behaving as a standard controller, exactly as the real one toggled — which is the fix
for games that predate the sticks and get confused by them.

For a real gamepad, spawn a **Controller Receiver** and plug that in instead — see
[controllers and peripherals](/guide/playing/controllers/).

## The serial link

The PlayStation's **SERIAL I/O** socket on the back is wired. Run a link cable between two
consoles and games that supported it will see each other — see [link
cables](/guide/playing/link-cables/).

## Cores

The PlayStation has several libretro cores with different accuracy and speed trade-offs.
Pick the default in `CORES` → **Manager** — see [downloading and managing
cores](/guide/cores/downloading/).
